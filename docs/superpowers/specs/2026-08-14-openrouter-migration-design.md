# Перенос языковой модели на OpenRouter

Дата: 14 августа 2026 года.

## Цель

Полностью заменить интеграцию с Evolution Foundation Models на OpenRouter во всём поддерживаемом коде, настройках и документации проекта. Сохранить существующие сценарии планирования, формирования финансового отчёта, структурированного ответа и вызова инструментов.

## Границы изменений

В работу входят:

- клиент языковой модели и его фабрика;
- подключение клиента к планировщику и формированию отчёта;
- переменные окружения и конфигурация Docker Compose;
- журналы использования модели;
- модульные и интеграционные проверки;
- основная, архитектурная и эксплуатационная документация;
- удаление поддерживаемых настроек и упоминаний Evolution Foundation Models и Cloud.ru.

Протоколы A2A и MCP сохраняются как независимые части архитектуры. Расчёты риска и получение данных Московской биржи не меняются.

## Архитектура

Класс `EvolutionLLMClient` заменяется классом `OpenRouterLLMClient`, а фабрика `build_evolution_llm_client_from_env` — фабрикой `build_openrouter_llm_client_from_env`.

Клиент продолжает использовать `AsyncOpenAI`, поскольку OpenRouter предоставляет совместимый интерфейс. Базовый адрес фиксируется значением `https://openrouter.ai/api/v1`, но может быть переопределён для проверок. Клиент передаёт необязательные заголовки идентификации приложения:

- `HTTP-Referer` из `OPENROUTER_SITE_URL`;
- `X-OpenRouter-Title` из `OPENROUTER_APP_NAME`.

Один экземпляр клиента используется планировщиком и формирователем отчёта. Это сохраняет текущую схему внедрения зависимости и не создаёт преждевременного разделения моделей по ролям.

## Модели и рассуждение

Значения по умолчанию:

- основная модель: `google/gemini-3.7-flash`;
- резервная модель: `openai/gpt-5.6-luna`;
- уровень рассуждения: `low`.

Основная модель используется первой во всех окружениях. Резервная модель вызывается после исчерпания допустимых повторов основной модели. Уровень рассуждения передаётся через поле OpenRouter `reasoning.effort` и может быть переопределён переменной окружения.

Не используются автоматический и бесплатный маршрутизаторы OpenRouter, чтобы модель, качество структурированного ответа и стоимость оставались предсказуемыми.

## Переменные окружения

Поддерживаются только новые настройки:

```dotenv
OPENROUTER_API_KEY=
OPENROUTER_API_BASE=https://openrouter.ai/api/v1
OPENROUTER_MODEL=google/gemini-3.7-flash
OPENROUTER_FALLBACK_MODEL=openai/gpt-5.6-luna
OPENROUTER_REASONING_EFFORT=low
OPENROUTER_SITE_URL=http://localhost:3000
OPENROUTER_APP_NAME=MOEX Market Analyst
```

Переменные `LLM_*`, `EVOLUTION_*` и адрес Evolution Foundation Models удаляются. Обратная совместимость с ними намеренно не сохраняется, поскольку согласована полная замена поставщика.

Если `OPENROUTER_API_KEY` отсутствует, фабрика возвращает `None`, и проект использует существующие детерминированные имитации модели. Это позволяет запускать интерфейс и проверки без внешнего ключа.

## Поток запроса

1. Сервер создаёт `OpenRouterLLMClient` из переменных окружения.
2. Планировщик отправляет системную инструкцию, пользовательский запрос, схему ответа и низкий уровень рассуждения в Gemini 3.7 Flash.
3. После выполнения инструментов тот же клиент формирует финансовый отчёт по фактическим данным.
4. При временной ошибке выполняются повторы с экспоненциальной задержкой.
5. После исчерпания повторов запрос направляется GPT-5.6 Luna.
6. Если внешний клиент недоступен, существующая логика возвращает контролируемый частичный или шаблонный ответ.

## Структурированные ответы

Сохраняется текущая последовательность восстановления:

1. ответ по схеме JSON;
2. ответ в виде объекта JSON, если схема не поддержана;
3. вызов инструмента, если модель не вернула допустимый объект;
4. переход к резервной модели после неудачи текущей модели.

Публичный метод `generate` сохраняет текущую сигнатуру, чтобы планировщик и формирователь отчёта не зависели от особенностей OpenRouter.

## Ошибки и повторы

Повторяются ошибки ограничения частоты, соединения, превышения времени ожидания и ответы сервера с кодами 429 или 5xx. Ошибки авторизации и некорректной конфигурации не повторяются бесконечно.

Сообщения журналов называют OpenRouter и фактически вызванную модель. Секретный ключ, системные инструкции, пользовательские запросы и финансовые данные в журнал не записываются.

## Учёт использования

Если ответ содержит сведения об использовании, клиент записывает на информационном уровне:

- запрошенную и фактически использованную модель;
- количество входных, сохранённых и выходных токенов;
- стоимость, если OpenRouter вернул её в ответе.

Отсутствие этих полей не считается ошибкой. Изменение внешнего интерфейса клиента ради статистики не требуется.

## Документация

Основной файл с инструкцией, примеры окружения, архитектурные документы и руководство по развёртыванию описывают OpenRouter. Руководство `docs/EVOLUTION_DEPLOY.md` заменяется нейтральным руководством развёртывания с OpenRouter. Названия классов, пояснения и примеры команд больше не ссылаются на Evolution Foundation Models или Cloud.ru.

## Проверки

Разработка выполняется через проверки до реализации. Необходимые сценарии:

- создание клиента с `OPENROUTER_API_KEY`;
- отказ от создания внешнего клиента без ключа;
- базовый адрес OpenRouter и необязательные заголовки приложения;
- основная модель Gemini 3.7 Flash;
- переход на GPT-5.6 Luna после временной ошибки;
- передача `reasoning.effort=low`;
- ответ по схеме JSON и существующие способы восстановления;
- повтор только допустимых временных ошибок;
- безопасное журналирование статистики;
- подключение новой фабрики сервером и планировщиком;
- прохождение существующего набора проверок;
- успешная сборка контейнеров;
- отсутствие старых переменных и активных упоминаний Evolution в отслеживаемых файлах.

## Критерии завершения

Работа завершена, когда:

- проект запускается без настроек Evolution;
- при наличии `OPENROUTER_API_KEY` оба обращения к модели идут через OpenRouter;
- Gemini 3.7 Flash используется первой, GPT-5.6 Luna — резервной;
- без ключа сохраняется локальная имитация модели;
- все автоматические проверки и сборка проходят;
- документация содержит рабочий порядок локального запуска с OpenRouter;
- поиск по отслеживаемым файлам не находит прежних названий клиента, переменных и адреса Foundation Models.
